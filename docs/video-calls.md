# Аудио/видеовстречи

Расширение после сдачи исходного ТЗ, ветка `feat/video-calls`. Используются
`livekit-client`, `@livekit/components-react`, `@livekit/components-styles` и
официальный Python SDK `livekit-api`. Медиа передаётся через LiveKit, а не FastAPI.

## Локальный запуск

Из корня репозитория, с установленными uv/Python и работающим Docker Engine:

```sh
uv sync --project backend --frozen
uv run --project backend python -m crm.modules.video_calls.configure
docker compose --profile video up -d --build --wait
docker compose exec backend /app/.venv/bin/python -m crm.seed
```

Команда настройки генерирует сильные случайные ключи в `.env` и `backend/.env`,
добавляя только настройки видеосвязи. Другие значения окружения сохраняются;
повторный запуск сохраняет уже созданные ключи. Менеджер должен существовать в БД;
seed создаёт менеджеров 1 и 2.
Скрипт предназначен для рабочего checkout репозитория и локального LiveKit.

Создайте аккаунт по [инструкции безопасности](security.md) и войдите в CRM по
логину и паролю. Видеокомната использует общую сессию, отдельный ключ менеджера
больше не нужен. Серверные ключи LiveKit остаются в `.env`.

Интерфейс: `http://localhost:3000`. В карточке организации у активной встречи
нажмите **Видеосозвон**. Откроется отдельная вкладка:

1. Откройте встречу под своим аккаунтом и создайте комнату.
2. Нажмите **Пригласить гостя** и передайте полученную ссылку участнику.
3. За 15 минут до встречи появится проверка устройств и кнопка входа.
4. Проверьте имя, микрофон и камеру; по умолчанию устройства выключены.
5. Войдите в комнату. Кнопки микрофона и камеры переключают передачу медиа.
6. **Выйти** отключает только текущего участника и позволяет войти заново.
   **Завершить созвон** у менеджера закрывает комнату для всех.

Для теста можно открыть приглашение во втором профиле браузера или приватном
окне на том же компьютере. Одно устройство может быть недоступно двум браузерам
одновременно: используйте разные камеры или выключите камеру в одном окне.

Настройка Compose предназначена для localhost: 7880 — HTTP/WebSocket,
7881 — RTC TCP, 7882 — RTC UDP. Все порты опубликованы на loopback, а ICE адрес
сервера — `127.0.0.1`. Другому компьютеру такая ссылка не даст медиасвязь:
для интернета нужны HTTPS/WSS, домен, доступные ICE-порты и TURN либо LiveKit Cloud.

Для запуска backend/frontend вне контейнеров используйте команды dev из README;
дополнительно запустите `docker compose --profile video up -d livekit`.
`backend/.env` уже содержит адрес LiveKit с хоста, корневой `.env` — адрес внутри
Compose. После изменения окружения перезапустите соответствующий процесс.

## Доступ и жизненный цикл

- Один назначенный менеджер и один гость; третья роль не предусмотрена.
  Повторный вход той же роли заменяет её прежнее подключение.
- Комната и приглашение создаются заранее, вход — от 15 минут до начала до
  15 минут после конца встречи. Даты API — UTC, интерфейс — Asia/Almaty.
- Приглашение случайное, в БД хранится только SHA-256. Секрет находится во
  fragment ссылки и передаётся API в теле POST. После чтения он удаляется из
  адресной строки: для перезагрузки гостю нужно заново открыть исходную ссылку.
- Повторная выдача приглашения запрещает новые входы по старой ссылке;
  уже подключённого гостя она сама по себе не отключает.
- Отмена/завершение встречи запрещает новую выдачу токенов сразу при commit.
  Перенос отзывает приглашение и старую комнату; нужно создать новую и пригласить
  гостя повторно. Изменение менеджера также передаёт право управления.
- Завершение созвона закрывает комнату, сохраняя текущий статус встречи CRM.
  Выход участника и обрыв сети не завершают встречу.
- Комнаты удаляет фоновый обработчик: период 10 секунд, ошибки повторяются,
  очередь сохраняется в PostgreSQL. При недоступности LiveKit фактическое
  отключение участников задерживается до восстановления связи.
- В self-hosted конфигурации обязательно `room.auto_create: false`. Сервер
  обновляет токены активных клиентов, поэтому короткий JWT не заменяет удаление
  комнаты. Для Cloud также отключите автоматическое создание комнат в проекте.
- Сессия менеджера находится в HttpOnly cookie; приглашения и JWT не помещаются
  в Query cache/localStorage. У ответов API — `Cache-Control: no-store`.

Все CRM endpoints требуют входа; права менеджера и администратора проверяются
на backend. Комната привязана к сессии ведущего: отзыв/истечение сессии запрещает
новые подключения и ставит комнату на закрытие. HTTPS/WSS, локальный CA и лимиты
попыток входа описаны в [security.md](security.md).
Запись, чат, демонстрация экрана и групповые звонки в этот этап не входят.

## API

Все менеджерские запросы требуют cookie-сессию; изменяющие — также `X-CSRF-Token`
и разрешённый `Origin`. Статические bearer-ключи больше не принимаются.
Интеграция включается через `CRM_VIDEO_ENABLED=true`; иначе `/video/*` отвечает 503.

| Метод и путь | Назначение |
| --- | --- |
| `GET /video/meetings/{id}` | Метаданные и состояние комнаты своей встречи |
| `POST /video/meetings/{id}/room` | Создать запись комнаты, повтор безопасен |
| `POST /video/meetings/{id}/invitation` | Выдать/заменить приглашение, ответ `url`, `expires_at` |
| `POST /video/meetings/{id}/join` | Получить токен подключения, тело `{"name":"Менеджер"}` |
| `POST /video/meetings/{id}/close` | Закрыть комнату, повтор безопасен, ответ 204 |
| `POST /video/guest` | Метаданные по приглашению, тело `{"invitation":"..."}` |
| `POST /video/guest/join` | Токен гостя, тело `{"invitation":"...","name":"Гость"}` |

Ответ подключения: `server_url`, `participant_token`, `room_name`. Токен выдаётся
на 60 секунд для одной комнаты с публикацией только камеры/микрофона, без
административных прав. Создание на медиасервере выполняется при подключении;
повтор после таймаута использует сохранённое имя комнаты.
401 — неверный ключ; 403 — чужая встреча/недействительное приглашение;
404 — нет встречи/комнаты; 409 — закрытая комната или вход вне окна;
422 — неверное тело; 503 — интеграция отключена либо медиасервер недоступен.

## Автоматические проверки

Backend-тесты запускаются обычным `uv run pytest -q` из backend с отдельной
`crm_test` по инструкции README. Платформа в интеграционных тестах подменяется
адаптером, проверка подписи и разрешений JWT выполняется настоящим SDK.

Для реальной связи в браузерных тестах, из корня:

```sh
docker compose --profile test --profile test-video up -d --wait postgres-test livekit-test
uv sync --project backend --frozen
cd frontend
npm ci
npm run test:e2e:video
```

Предварительно настройте `backend/.env.test` по README. Нужны Edge на Windows
либо установленный Playwright Chromium на Linux/macOS. Проверка использует
синтетические камеру/микрофон и два независимых браузерных контекста, сравнивает
полученные аудиобайты и декодированные видеокадры через WebRTC stats.
Проверяются вход, управление устройствами, выход, повторный вход, закрытие и
ошибочные приглашения. Порты 3001/18001/17880/17881/17882 должны быть свободны.

Тестовый LiveKit использует отдельные публичные фиктивные ключи из
`infra/livekit-test.yaml`, API — только БД `crm_test`. Её содержимое очищается;
не запускайте вместе с pytest или другим E2E-набором против той же БД.
Обычный `npm run test:e2e` проверяет CRM с выключенной видеосвязью.
Тестовые снимки сохраняются в игнорируемой `.cache`, диагностические файлы —
в `frontend/test-results`. Реальные ключи окружения в тестах не используются.

Автотест с синтетическими устройствами не заменяет ручную проверку качества звука,
эха и соединения двух физических устройств в разных сетях.
